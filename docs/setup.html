FÜR LEHRENDE / EINRICHTUNG

Dein Kurs.
Dein Bildlabor.

Einrichtung im Browser. Keine Installation auf den Pool-Rechnern.
Deinen OpenAI-Key trägst du ausschließlich bei Cloudflare ein.

Diese Seite bereitet Dateien vor. Sie hat keinen Verwaltungszugriff auf deinen Worker. Kurscodes werden erst gültig, nachdem du ihre SQL-Daten in deiner Cloudflare-Datenbank ausgeführt hast.

01 / CLOUDFLARE WORKER

Der sichere Zugang zu OpenAI

  1. Öffne das Cloudflare Dashboard ↗. Gehe zu Workers & Pages → Create application und erstelle einen Worker (z. B. mit „Hello World“). Nenne ihn bildlabor-api.
  2. Öffne Edit code. Ersetze den Beispielcode vollständig durch den vorbereiteten Worker-Code und klicke Deploy.
  3. Notiere die Adresse https://bildlabor-api.DEIN-NAME.workers.dev.
Worker-Code herunterladen ↓

Alternativ: Worker-Code im Browser öffnen, alles markieren und kopieren.

02 / KONTINGENTE

Eine kleine Datenbank verbinden

  1. In Cloudflare: Storage & databases → D1 SQL Database → Create database. Name: bildlabor.
  2. Öffne die Datenbank und ihre Console. Führe den Inhalt von schema.sql aus. Falls die Konsole mehrere Anweisungen nicht zusammen akzeptiert, führe die CREATE-Anweisungen einzeln aus; der gesamte CREATE-TRIGGER-Block ist eine Anweisung.
  3. Zurück zum Worker: Bindings → Add binding → D1 database. Variablenname exakt DB, Datenbank bildlabor. Speichern und gegebenenfalls erneut deployen.

Die Datenbank speichert Code-Hashes, Zähler, Ablaufdatum und den Status eines Versuchs. Keine Prompts oder Bilder.

03 / GEHEIMNISSE

Den API-Key nur bei Cloudflare hinterlegen

Worker → Settings → Variables and Secrets → Add:

  • Secret OPENAI_API_KEY: dein OpenAI-Projekt-Key.
  • Text ALLOWED_ORIGIN: https://DEIN-GITHUB-NAME.github.io – ohne Repository-Pfad und ohne abschließenden Schrägstrich.

Speichern und deployen. API-Nutzung verursacht Kosten auf deinem OpenAI-Projekt. Der Worker erlaubt nur feste Modelle, zwei Qualitätsstufen und ein Bild pro Versuch. Die Kontingente begrenzen Versuche, keinen exakten Eurobetrag.

04 / KURSCODES

Zugänge für deine Studierenden erstellen

Jede Person erhält einen eigenen zufälligen Code. Auch fehlgeschlagene API-Versuche zählen, damit Wiederholungen das Kostenlimit nicht umgehen. Codes und Downloads nicht ins öffentliche Repository hochladen.

Die Code-Liste jetzt herunterladen und privat aufbewahren. Sie ist nach dem Schließen nicht wiederherstellbar. Die SQL-Datei enthält nur Hashes. Erneutes Ausführen derselben SQL-Datei setzt verbrauchte Versuche nicht zurück.

05 / GITHUB PAGES VERBINDEN

Eine öffentliche URL, keine geheimen Schlüssel

  1. Erstelle auf GitHub ein Repository, z. B. bildlabor. Für GitHub Free kann es öffentlich sein – der Code enthält keine Zugangsdaten.
  2. Lade den gesamten Inhalt des Paketordners hoch, sodass docs/index.html existiert. Ersetze docs/config.js durch die gerade heruntergeladene Datei.
  3. Im Repository: Settings → Pages → Deploy from a branch → main → /docs → Save.
  4. Öffne deine veröffentlichte Seite, melde dich mit einem Testcode an und erstelle ein Testbild. Gib erst danach den Link und die persönlichen Codes an die Gruppe weiter.

Die Verbindungsprüfung muss von der in ALLOWED_ORIGIN eingetragenen Website erfolgen. Eine lokale Vorschau hat eine andere Herkunft und wird absichtlich abgewiesen.

KURS VERWALTEN

Pause, Überblick und Abschluss

In der D1 Console ausführen:

-- Kurs pausieren (verhindert neue Starts)
UPDATE campaign SET enabled = 0 WHERE id = 1;

-- Kurs wieder öffnen
UPDATE campaign SET enabled = 1 WHERE id = 1;

-- Verbrauch ansehen
SELECT label, used, quota, datetime(expires_at, 'unixepoch') AS expires_utc FROM codes;
SELECT used, total_limit, enabled FROM campaign;

-- Einen Code sperren (Label aus der Code-Liste einsetzen)
UPDATE codes SET enabled = 0 WHERE label = 'DEIN-CODE-LABEL';

Bereits gestartete Generierungen können beim Pausieren noch abgeschlossen werden. Zähler nicht während laufender Versuche zurücksetzen. Für einen neuen Kurs empfiehlt sich eine neue Datenbank.
